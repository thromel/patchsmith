# Glossary

## Agent runtime

The orchestration implementation used to execute the repair workflow. Examples include LangGraph, DeepAgents, OpenAI Agents SDK, Agentless baseline, or tree-search runtime.

## Agentless baseline

A simple three-phase approach that avoids complex agent loops: localize files, generate repair, validate patch. It is used as a baseline against more complex scaffolds.

## Code Context Graph

A graph representation of the repository. It links files, symbols, imports, tests, stack traces, issue mentions, and patch candidates.

## Context packing

The process of selecting and formatting retrieved repository context for model input while respecting token and relevance budgets.

## DeepAgents runtime

An experimental DeepAgents-backed runtime behind PatchSmith's bounded planner/edit contract. It supports offline adapter evidence and native live-model planning; current saved live evidence uses `deepagents_openai_chat` on `gpt-5.4-mini`.

## OpenAI Agents runtime

An experimental runtime adapter for the OpenAI Agents SDK scaffold. Current local evidence uses dependency-gated offline compatibility mode behind PatchSmith's bounded planner/edit contract; live OpenAI Agents package/model execution is a separate calibration step.

## Evaluation harness

The system that runs tasks across configurations and records metrics, artifacts, and reports.

## Fault localization

The process of identifying files, symbols, tests, or code regions likely related to an issue.

## Human approval gate

A checkpoint requiring explicit human approval before actions such as pushing code, opening a pull request, enabling network access, or accepting self-generated skills.

## Patch candidate

One proposed diff generated by the system. Patch search may generate several candidates and select the strongest one.

## Patch search

A test-time strategy where the system generates multiple candidate patches, runs tests, analyzes failures, and selects a final patch using evidence.

## PR-ready patch

A patch that is ready for human review and potential pull request creation. It does not mean the system automatically opens or merges a PR.

## Retrieval hit rate

The percentage of tasks where retrieval includes one or more files that are part of the reference or expected fix.

## Run

One issue-to-patch attempt for a specific repository snapshot and configuration.

## Sandbox

An isolated execution environment used to run repository commands and tests safely.

## Scaffold

The structure around the model: tools, prompts, memory, state transitions, retry loops, and execution policy.

## Seeded bug suite

A controlled evaluation dataset made of small repositories with known injected bugs and known expected touched files.

## Skill registry

A gated collection of reusable debugging strategies produced from previous runs and accepted only after evaluation.

## Trace event

A structured record of a run step, such as a model call, tool call, patch application, test run, or retry decision.

## Tree-search mode

A research runtime that explores multiple reasoning or patch paths rather than following one linear repair trajectory.
