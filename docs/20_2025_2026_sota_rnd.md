# 2025-2026 SoTA R&D Notes

PatchSmith should not anchor its research story only on 2024-era SWE-bench
work. The 2025-2026 literature shifts the center of gravity from one-shot
bug-fixing toward context discipline, long-horizon maintenance, task
collection, runtime scaffolds, and quality gates that outlive a single passing
test.

## Reading Priority

### Context and Scaffold Design

| Paper | Why it matters for PatchSmith | Immediate takeaway |
| --- | --- | --- |
| [ACON: Optimizing Context Compression for Long-horizon LLM Agents](https://arxiv.org/abs/2510.00615) | Treats context compression as a learned guideline optimization problem driven by full-context-success / compressed-context-failure pairs. | Convert failed span-context runs into compression-guideline test cases instead of hand-tuning file caps only. |
| [Evaluating AGENTS.md](https://arxiv.org/abs/2602.11988) | Finds repository-level context files can reduce success and raise cost when they add unnecessary requirements. | Keep PatchSmith's repair interface minimal, task-local, and measurable; do not mount broad policy text unless it earns its tokens. |
| [Context Engineering for AI Agents in OSS](https://arxiv.org/abs/2510.21413) | Shows context files are adopted inconsistently and mix descriptive, prescriptive, prohibitive, explanatory, and conditional content. | Split PatchSmith context into typed channels: facts, constraints, commands, risks, hints, and history. |
| [Anthropic: Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) | Frames long-horizon work around compaction, structured notes, and multi-agent architectures while warning that context windows still suffer pollution and relevance issues. | Keep PatchSmith's repair interface and saved notes compact, and measure whether mounted context is earning its tokens. |
| [OpenHands Software Agent SDK](https://arxiv.org/abs/2511.03690) | Frames production agents around composable interfaces, sandboxed execution, lifecycle control, model routing, and event history. | PatchSmith's value is the evidence harness around agents, not only the planner prompt. Preserve event-sourced traces and sandbox portability. |
| [LangChain Deep Agents overview](https://docs.langchain.com/oss/python/deepagents/overview) | Treats a deep agent as an agent harness with planning, filesystem-backed context management, subagents, memory, human-in-the-loop, and improvement from usage. | Keep DeepAgents as PatchSmith's primary live planner, but gate subagents and memory features through token/cost telemetry. |
| [Live-SWE-agent](https://arxiv.org/abs/2511.13646) | Shows runtime scaffold evolution can outperform manually designed agents on SWE-bench Verified and SWE-Bench Pro. | Try scaffold self-improvement as gated config/protocol proposals evaluated offline before promotion, not arbitrary live mutation. |
| [Confucius Code Agent](https://arxiv.org/abs/2512.10398) | Emphasizes scalable scaffolds, persistent notes, advanced context management, extension systems, and meta-agent build-test-improve loops. | Add a controlled meta-eval lane for proposing context-policy or retry-policy changes, with benchmark-only promotion. |
| [Retrospective Harness Optimization](https://arxiv.org/abs/2606.05922) | Uses a difficulty-diverse coreset of prior trajectories, repeated rollouts, self-validation, and self-consistency to propose harness improvements without ground-truth labels. | Use PatchSmith's saved traces to select the next informative rerun cohort before spending on live A/Bs. |
| [Adaptive Auto-Harness](https://arxiv.org/abs/2606.01770) | Separates sustained harness construction from solve-time routing across heterogeneous task streams. | Keep PatchSmith harness changes branchable and task-routed; do not promote one dense policy from a small smoke lane. |
| [SWE-Manager](https://arxiv.org/abs/2601.22956) | Treats issue resolution as selecting and synthesizing a "golden" proposal before implementation, closer to how maintainers review competing fixes. | Add a proposal/verifier step before final patch acceptance; benchmark selected-patch quality separately from raw patch generation. |
| [Agentic Rubrics as Contextual Verifiers for SWE Agents](https://arxiv.org/abs/2601.04171) | Uses repository-grounded rubric checklists as interpretable verification signals for candidate patches, reducing reliance on execution-only feedback. | Mount a task-local acceptance rubric for DeepAgents and report whether saved traces read it before final output. |

### Evaluation and Benchmarks

| Paper | Why it matters for PatchSmith | Immediate takeaway |
| --- | --- | --- |
| [SWE-Bench Pro](https://arxiv.org/abs/2509.16941) | Moves beyond small repairs to realistic enterprise-level, long-horizon tasks across many repos. | Keep public-issue claims caveated until PatchSmith has multi-file and long-horizon saved artifacts. |
| [SWE-rebench](https://arxiv.org/abs/2505.20411) | Continuously extracts fresh interactive tasks from GitHub to reduce contamination and provide real environment interaction at scale. | Keep PatchSmith's public-issue smoke lane fresh and clearly separate cached/saved evidence from newly executed model calls. |
| [SWE-Compass](https://arxiv.org/abs/2511.05459) | Unifies multiple agentic coding task types, languages, and scenarios instead of treating Python bug fixing as the whole field. | Label PatchSmith's current lane as public-issue repair only; add separate feature, performance, review, and multi-language lanes before making broader claims. |
| [ContextBench](https://arxiv.org/abs/2602.05892) | Adds human-annotated gold contexts and process metrics for context recall, precision, and efficiency across issue-resolution trajectories. | Report context-efficiency proxies and trace-derived target/context recall now, then add human gold-context recall/precision when PatchSmith has reviewed target contexts. |
| [SWE-Explore](https://arxiv.org/abs/2606.07297) | Benchmarks repository exploration by deriving core and optional context from solution-verified trajectories, then evaluating whether restricted context still supports solving. | Treat CLI-agent repository exploration as its own benchmark surface: measure what the agent reads before editing, not only whether the final patch validates. |
| [LoCoBench-Agent](https://arxiv.org/abs/2511.13998) | Evaluates multi-turn long-context software workflows, tool usage efficiency, error recovery, and architectural consistency across extended sessions. | Add conversation-efficiency and recovery metrics to complex reports instead of relying only on final validation. |
| [FeatureBench](https://arxiv.org/abs/2602.10975) | Uses execution-based, feature-oriented tasks mined from repositories; strong SWE-bench agents drop sharply. | Add a feature-development lane, not only bug repair. |
| [SWE-EVO](https://arxiv.org/abs/2512.18470) | Builds release-note-driven long-horizon tasks averaging many touched files and introduces partial progress scoring. | Add Fix Rate style metrics for complex tasks so partial progress is not hidden by binary pass/fail. |
| [SWE-Cycle](https://arxiv.org/abs/2605.13139) | Evaluates environment reconstruction, implementation, verification-test generation, and an end-to-end full cycle, exposing drops when agents must handle cross-phase dependencies. | Add setup and verification-generation lanes before claiming full lifecycle autonomy. |
| [RoadmapBench](https://arxiv.org/abs/2605.15846) | Evaluates version-upgrade roadmaps across many files, languages, and independent targets; even frontier agents remain far below one-shot bug-fix performance. | Treat multi-target planning and target dependency tracking as a future benchmark axis, not just bigger public-issue tasks. |
| [SWE-CI](https://arxiv.org/abs/2603.03823) | Evaluates maintainability by replaying long development histories through CI. | Add commit-replay or future-test validation for patches that pass current tests. |
| [SlopCodeBench](https://arxiv.org/abs/2603.24755) | Measures structural erosion and verbosity under repeated extension. | Promote patch-quality metrics to first-class benchmark output: diff size, duplicate code, complexity concentration, and follow-up extensibility. |
| [CodeClash](https://arxiv.org/abs/2511.00839) | Evaluates goal-oriented, open-ended iterative development through multi-round tournaments. | Keep this as a stretch benchmark idea after PatchSmith has stronger issue and feature lanes. |
| [NoCode-bench](https://arxiv.org/abs/2507.18130) | Evaluates doc-driven feature implementation; high token use but low task success. | Use documentation deltas as a future input format for feature repair tasks. |
| [SWE-Perf](https://arxiv.org/abs/2507.12415) | Tests repository-level performance optimization, where existing agents still show a large gap. | Performance tasks need different validation artifacts: benchmark commands, runtime deltas, and regression checks. |
| [SWE-fficiency](https://arxiv.org/abs/2511.06090) | Focuses on repository-level performance optimization against real workloads and expert speedups. | PatchSmith needs workload traces and speedup preservation checks before claiming optimization-agent readiness. |
| [Code Review Agent Benchmark](https://arxiv.org/abs/2603.23448) | Builds a benchmark for evaluating agent review quality against human review-derived tests. | Treat PatchSmith's patch-reviewer as an evaluated component, not just a prompt helper. |
| [AgentLens](https://arxiv.org/abs/2605.12925) | Shows that pass/fail-only SWE-agent evaluation hides "lucky passes" with blind retries, missing verification, and disordered trajectories. | Keep process-quality labels and risky-pass gates beside validation rate in every complex suite. |
| [HarnessFix](https://arxiv.org/abs/2606.06324) | Diagnoses failed agent trajectories by mapping evidence to harness layers before proposing scoped harness repairs. | Use harness-layer counts to decide whether the next change belongs in context, retry, validation, sandbox, or budget policy. |
| [SWE-Replay](https://arxiv.org/abs/2601.22129) | Reuses prior trajectories by branching from critical intermediate steps, reducing sampling cost without relying on LLM-as-judge value estimates. | Rank saved PatchSmith attempts for follow-up reruns using deterministic trace evidence before sampling from scratch again. |

## Design Changes To Consider

1. Add a context-policy ablation lane:
   - no broad repo context,
   - minimal repair interface,
   - focused span context,
   - full retrieved context,
   - optional scoped repository instructions mounted as
     `/.patchsmith/repo-instructions.md` only from AGENTS.md-style files that
     apply to mounted paths.

2. Convert failed live runs into compression tests:
   - preserve the full-context trace,
   - preserve the compressed-context trace,
   - classify which fact was lost,
   - update compression guidance only when the failure class is reproducible.

3. Add target-selection evidence before patch generation:
   - expose candidate control points,
   - require the planner to pick a patchable path from ranked candidates,
   - record why ignored candidates were rejected.

4. Promote patch quality from an afterthought to a benchmark dimension:
   - patch size,
   - touched files,
   - duplicate code,
   - complexity concentration,
   - risky broad edits,
   - future-test or commit-replay survival.

5. Add contextual verifier artifacts before final patch output:
   - generate a task-local acceptance rubric from issue evidence, mounted files,
     preferred target paths/symbols, validation fixtures, and unsafe-patch
     exclusions,
   - mount it as `/.patchsmith/acceptance-rubric.md`,
   - record rubric manifest coverage and read-first rate in complex benchmark
     summaries,
   - compare validation, cost, target alignment, and quality warnings with and
     without the rubric before promoting stricter verifier gates.

6. Add context-efficiency reporting:
   - selected virtual files,
   - virtual files per validated task,
   - selected tokens per virtual file,
   - selected responses per virtual file,
   - selected context-target recall and precision from localized target paths
     versus mounted DeepAgents source paths,
   - suite gates for each selected context-efficiency proxy,
   - suite gates for minimum context-target recall and precision,
   - later, gold-context recall and precision when reviewed target contexts
     exist.

7. Add a guided retry artifact:
   - failed command,
   - observed stack or assertion,
   - selected failure class,
   - target hypothesis,
   - budget remaining,
   - allowed next edit scope.
   Current status: runtime feedback retries now include a deterministic
   `retry_failure_class`, focused next-step guidance, labels for aggregate trace
   analysis, a `feedback_retry` trace payload field, and complex benchmark
   `retry_failure_class_counts`. Complex reports now also include
   `process_quality_label_counts`, `process_quality_flag_counts`, and
   `process_risky_validated_tasks` so validated attempts with missing
   verification, blind retries, failed-event churn, or post-verification edits
   can be separated from cleaner passes. Suite specs and CLI runs can enforce
   this with `min_process_quality_score` and
   `max_process_risky_validated_tasks`.
   HarnessFix-style harness-layer attribution is now exposed as
   `harness_layer_counts` and `selected_harness_layer_counts`, separating
   failures into budget, model, sandbox, preflight, reproduction, planning,
   context, patch quality, retry, runtime, validation, and orchestration
   buckets.

8. Treat scaffold self-improvement as a controlled experiment:
   - agent proposes a planner/config/context-policy change,
   - PatchSmith stores it as a candidate patch,
   - offline benchmark gates decide whether it can be promoted.

9. Turn declared budgets into active runtime controls:
   - mount response/token limits in the repair interface,
   - block the next model response when the response cap is exhausted,
   - record `resource_budget_exceeded` as a first-class model status,
   - keep token overages as strict claim failures when provider usage arrives
     only after the response has already been generated.

10. Treat repository instruction files as scoped evidence, not free context:
   - discover root and mounted-path ancestor `AGENTS.md`, `CLAUDE.md`,
     `GEMINI.md`, and `.cursorrules` files,
   - cap count and size before mounting,
   - record `repo_instructions_manifest_path` and read-first metadata,
   - gate manifest/read-first coverage only in explicit context-policy lanes,
   - compare validation, cost, target alignment, and exploration behavior
     before enabling any hard gate.

11. Report partial progress for complex tasks:
   - compute a selected-attempt progress score from saved trace evidence,
   - distinguish reproduced input, patch generation, target-aligned patches,
     quality-warning test passes, and clean validation,
   - use `min_selected_progress_score` only as an opt-in suite floor, never as
     a substitute for validation-rate gates.

12. Add deterministic failure-class telemetry:
   - label saved attempts as validated, quality-risk, preflight-blocked,
     reproduction-failed, no-patch, target-misaligned, runtime/tool failure,
     retry-exhausted, or validation-failed,
   - report both all-attempt and selected-attempt counts,
   - keep the labels artifact-derived and avoid presenting them as human
     root-cause annotations.

13. Add trajectory-informed follow-up cohort selection:
   - rank saved attempts before the next live A/B lane,
   - prioritize strict failures, harness-layer signals, process-risk labels,
     retry failure classes, target misalignment, and cost/token outliers,
   - write `complex_benchmark_followup_candidates.json` and a report section so
     the next run is chosen from evidence instead of recency or intuition,
   - return the same candidates from `eval-complex-suite --json` so scripts can
     pick the next live task/profile without scraping Markdown,
   - attach rule-based `action` and `suggested_profile` fields such as
     `cost_optimization_rerun` / `budget_critical_context_cap`,
     `quality_gate_rerun` / `acceptance_rubric_verifier`, and
     `context_policy_ablation` / `targeted_context_ablation`,
   - include `recommended_command` and `recommended_env` so the selected
     follow-up can be launched once live credentials are available,
   - include `validation_command` and `success_criteria` so the bounded rerun
   is immediately checked against validation, live-provider, cost, token,
   response, process-quality, and target-alignment gates.

14. Promote the daily-use CLI as a first-class research surface:
   - expose `patchsmith agent` for one-shot automation and `patchsmith chat`
     / `patchsmith agent --interactive` for conversational repair sessions,
   - default to current repo, DeepAgents, native hybrid context, auto subagent

   - keep direct worktree mutation out of the default path until an explicit
     `--apply` flow has the same bounded patch, validation, and artifact gates,
   - keep slash commands small and auditable first: `/preflight`, `/context`,

     `/export`, `/sessions`, `/commands`, `/hooks`, `/agents`, `/agent`,

     `/exit`,
   - support project-local custom slash commands as Markdown prompt templates

     validation, or apply boundaries,
   - parse lightweight command frontmatter such as `description` and
     `argument_hint`, and expose command metadata through `--list-commands
     --json` so project commands are discoverable by both humans and scripted
     agent integrations,
   - support project-local lifecycle hooks under `.patchsmith/hooks.json`, so

   - expose hook metadata through `/hooks` and `--list-hooks --json`, matching

   - support project-local agent profiles under `.patchsmith/agents/`, matching

   - expose profile metadata through `/agents`, `/agent <name>`,

   - load concise AGENTS.md/CLAUDE.md-style project instructions into the

   - expose `/permissions` as the first local action-confirmation surface,

     without weakening PatchSmith's existing diff and worktree checks,
   - expose `/rewind` / `/undo` as the first checkpoint-style recovery surface:

     keep unrelated worktree state intact, and record rewind attempts/successes
     in transcript metrics,
   - record context-hint mutations before the next run so interactive context

   - record model and budget mutations before the next run so live model

   - expose a local `/doctor` command so missing optional dependencies,

   - expose `/gate` in chat so users can run validated, clean, applied, and

   - expose `/trace` and `/evidence` in chat so the last run's report, trace,

## Working Hypothesis

The useful PatchSmith angle is not "another coding agent." The sharper claim is:

> PatchSmith is an evidence harness for studying how context, scaffold policy,
> retry guidance, and validation strength affect software-maintenance agents
> under realistic cost and quality constraints.

That framing matches the newer literature better than a simple SWE-bench-style
repair leaderboard.
